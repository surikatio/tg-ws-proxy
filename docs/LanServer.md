# Прокси для локальной сети (Linux-сервер)

Один прокси на домашнем сервере или мини-ПК, к которому подключаются все устройства в сети: компьютеры, телефоны, планшеты.

## Быстрый старт

```bash
pip install -e .
tg-ws-proxy --lan
```

Флаг `--lan` делает три вещи:

- слушает `0.0.0.0` — то есть доступен со всех устройств в сети, а не только локально;
- хранит секрет в файле (`~/.config/tg-ws-proxy/secret`, права `0600`) и переиспользует его при следующем запуске — **ссылки, которые вы раздали устройствам, продолжают работать после перезагрузки сервера**;
- печатает готовую ссылку для раздачи.

В логе будет:

```text
============================================================
  Share this link (clickable when sent in a Telegram chat):
    https://t.me/proxy?server=192.168.1.50&port=1443&secret=dd68f127db1d...
  Local link:
    tg://proxy?server=192.168.1.50&port=1443&secret=dd68f127db1d...
  Devices must be on the same network as 192.168.1.50
============================================================
```

Откройте порт в файрволе для своей подсети:

```bash
sudo ufw allow from 192.168.1.0/24 to any port 1443 proto tcp
```

## Как раздать подключение

Скопируйте **первую** ссылку (`https://t.me/proxy?...`) и отправьте её в любой чат — например, в «Избранное», а оттуда перешлите домашним.

Почему именно она: `tg://proxy?...` работает только как локальная ссылка на самой машине — при отправке в чат Telegram не сделает её кликабельной. Формат `https://t.me/proxy?...` кликается в любом клиенте и на любой платформе, а по нажатию открывает то же окно «Подключиться к прокси». Нажал — подключился, ничего вводить вручную не нужно.

В tray-приложении пункт **«Скопировать ссылку»** тоже копирует именно `t.me`-вариант, а «Открыть в Telegram» по-прежнему использует локальную `tg://`.

Если удобнее QR-код (для телефонов), скормите ту же ссылку любому генератору, например `qrencode -t ANSIUTF8 "https://t.me/proxy?..."`.

## Автозапуск через systemd

В репозитории есть готовый юнит [`packaging/tg-ws-proxy.service`](../packaging/tg-ws-proxy.service):

```bash
sudo cp packaging/tg-ws-proxy.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now tg-ws-proxy

# ссылка для раздачи
journalctl -u tg-ws-proxy | grep t.me
```

Юнит запускается под `DynamicUser` (свой одноразовый аккаунт без прав), секрет хранит в `/var/lib/tg-ws-proxy/secret`, и перезапускается при падении. Путь в `ExecStart` рассчитан на `pip install` (`/usr/local/bin/tg-ws-proxy`) — если ставили иначе, поправьте.

> [!WARNING]
> Готовые бинарники с релизов (`TgWsProxy_linux_amd64`, `.deb`, `.rpm`) — это **tray-приложение**, ему нужен графический сеанс. Для сервера без графики ставьте через `pip install`.

## Важные ограничения

- **Прокси работает только внутри вашей сети.** Когда телефон уходит на мобильный интернет, адрес `192.168.x.x` недоступен, и Telegram перестанет подключаться, пока прокси не отключить в настройках. Это плата за то, что сервер не выставлен наружу.
- **Не открывайте порт наружу «просто так».** Если пробросить 1443 через роутер в интернет, ваш прокси станет публичным для всех, у кого есть секрет, а сам факт MTProto-прокси на порту виден сканерам. Если это всё же нужно — включайте маскировку `--fake-tls-domain example.com` и ограничивайте `--max-connections`.
- **IP сервера должен быть постоянным.** Закрепите его в DHCP роутера, иначе после перезагрузки адрес сменится и все выданные ссылки перестанут работать.

## Полезные параметры

| Аргумент | Зачем |
|---|---|
| `--lan` | Слушать всю локальную сеть + постоянный секрет |
| `--secret-file PATH` | Свой путь к файлу секрета (в `--lan` включён автоматически) |
| `--max-connections N` | Предел одновременных подключений, `0` — без предела (по умолчанию 2048) |
| `--port N` | Другой порт, если 1443 занят |
| `--no-cfproxy` | Не обращаться к Cloudflare-фолбэкам и не скачивать список доменов с GitHub |
| `--fake-tls-domain DOMAIN` | Маскировка под TLS-трафик к указанному домену |
| `-v` | Подробный лог для диагностики |

Полный список — в [BuildFromSource.md](./BuildFromSource.md).

## Что уходит во внешнюю сеть

Прокси по своей задаче обязан ходить в интернет, полностью автономным он быть не может:

- **WebSocket к дата-центрам Telegram** (`kws*.web.telegram.org`) — основной канал, без него смысла нет;
- **список доменов Cloudflare-фолбэка** с `raw.githubusercontent.com` раз в час — отключается флагом `--no-cfproxy`, тогда обращений к GitHub не будет вовсе;
- **Cloudflare-фолбэки** — только если прямой WebSocket не прошёл.

Проверка обновлений есть только в tray-приложении; консольный `tg-ws-proxy` её не выполняет.
