# Android-приложение

Прокси работает прямо на телефоне: приложение поднимает MTProto-прокси на `127.0.0.1:1443`, а Telegram на том же устройстве подключается к нему. Ничего в локальной сети и никакого сервера не требуется — телефон самодостаточен, в том числе на мобильном интернете.

## Как это устроено

```
Telegram (телефон) → 127.0.0.1:1443 → приложение → WebSocket → Telegram DC
```

Приложение не переписывает протокол: внутри него работает тот же Python-пакет `proxy/`, что и на десктопе, — через [Chaquopy](https://chaquo.com/chaquopy/). Поэтому исправления в мосте, фолбэках и пуле соединений автоматически действуют и на телефоне.

Слои:

| Файл | Роль |
|---|---|
| `android/app/src/main/python/proxy_bridge.py` | Обёртка над ядром: `start` / `stop` / `status`, свой event loop |
| `ProxyService.kt` | Foreground-сервис, держит прокси живым и показывает уведомление |
| `MainActivity.kt` | Экран: запуск/остановка, «Подключить в Telegram», копирование секрета |
| `Prefs.kt` | Порт и постоянный секрет |

Ядро `proxy/` копируется в сборку Gradle-таском `syncProxyCore` — второй копии кода в репозитории нет.

## Сборка

Нужны Android Studio (или Android SDK) и интернет: Gradle скачает Chaquopy и рантайм Python. Python-пакеты из pypi **не требуются** — см. про `javax.crypto` ниже.

```bash
cd android
./gradlew assembleDebug          # Windows: gradlew.bat assembleDebug
```

APK окажется в `android/app/build/outputs/apk/debug/`. Проще открыть папку `android/` в Android Studio и нажать Run.

> [!WARNING]
> **Путь к проекту не должен содержать кириллицу.** Android Gradle Plugin отказывается собирать из каталогов с не-ASCII символами (`Your project path contains non-ASCII characters`). Если репозиторий лежит, например, в `C:\Users\...\Документы\питон проекты\`, скопируйте `android/` и `proxy/` в путь вида `C:\build\` и собирайте оттуда — структура должна сохраниться:
>
> ```
> C:\build\android\   ← сюда android/
> C:\build\proxy\     ← сюда proxy/
> ```

Файл `local.properties` создаётся Android Studio автоматически; вручную путь пишется с прямыми слэшами, иначе Java воспримет `\U`, `\t` и подобное как escape-последовательности:

```properties
sdk.dir=C:/Users/<user>/AppData/Local/Android/Sdk
```

### Подпись release-сборки

Отладочная сборка подписывается ключом, общим для всех разработчиков, и Play Protect относится к ней строже. Для release нужен свой ключ:

```bash
keytool -genkeypair -keystore ~/tgwsproxy-release.jks -alias tgwsproxy \
        -keyalg RSA -keysize 4096 -validity 10000
```

Затем скопируйте `keystore.properties.example` в `android/keystore.properties` и заполните путь и пароли. Файл в `.gitignore` — в репозиторий он не попадёт. Без него `assembleRelease` тоже работает, просто откатывается на отладочную подпись.

```bash
./gradlew assembleRelease     # app/build/outputs/apk/release/
```

> [!CAUTION]
> **Храните ключ и пароль.** Android разрешает обновление только сборкой с той же подписью. Потеряете ключ — новые версии придётся ставить через удаление приложения, а вместе с ним пропадёт сохранённый секрет и Telegram надо будет настраивать заново. По этой же причине версия с новой подписью не встанет поверх старой.

Предупреждение об установке не из Play Store останется в любом случае — его убирает только публикация в Google Play.

### Почему нет зависимостей pip

Колеса `cryptography` для Android не существует, а сборка из исходников требует Rust. Поэтому `proxy/_aes.py` получил третий бэкенд — через `javax.crypto`, который есть на любом Android-устройстве. Ядро выбирает его автоматически: `cryptography` → `javax.crypto` → системный `libcrypto`. Побочный плюс: сборке не нужен доступ к pypi.org.

Установка на подключённый телефон:

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

## Использование

1. Запустите приложение и нажмите **«Запустить»** — появится постоянное уведомление.
2. Нажмите **«Подключить в Telegram»**. Откроется окно подключения к прокси с уже заполненными адресом, портом и секретом — останется нажать «Подключиться».
3. Если Telegram не открылся, добавьте прокси вручную: тип **MTProto**, сервер `127.0.0.1`, порт `1443`, секрет — из приложения (кнопка «Скопировать секрет»).

Секрет сохраняется между запусками, поэтому настраивать Telegram нужно один раз.

## Что важно знать

- **Прокси живёт, пока висит уведомление.** Это foreground-сервис: без него Android заморозит процесс через несколько минут, и Telegram молча потеряет связь. Уведомление убрать нельзя — таково требование системы.
- **Отключите оптимизацию батареи** для приложения (Настройки → Приложения → TG WS Proxy → Батарея → «Без ограничений»), иначе агрессивные прошивки (Xiaomi, Huawei, Samsung) всё равно усыпят сервис.
- **Расход батареи выше**, чем у обычного Telegram: трафик проходит через дополнительный слой, а Python на телефоне не бесплатен. Для постоянного использования сервер в локальной сети или ZeroTier экономнее.
- **Размер APK ~40 МБ** — внутри рантайм Python и `cryptography` для двух ABI (`arm64-v8a`, `x86_64`).
- Прокси слушает только `127.0.0.1`, то есть доступен исключительно приложениям этого же телефона. Раздать его другим устройствам нельзя — для этого есть [режим локальной сети](./LanServer.md).

## Состояние

**Работает на устройстве.** `assembleDebug` собирает APK ~39 МБ для `arm64-v8a` и `x86_64`; приложение запускается, Telegram подключается к прокси и работает. Тем самым подтверждено и то, что AES-CTR через `javax.crypto` под Chaquopy считается верно — иначе handshake бы не прошёл.

Python-мост дополнительно протестирован на десктопе: запуск, приём подключений, статистика, остановка с освобождением порта.

Что стоит проверить при долгой эксплуатации: переживает ли сервис глубокий сон устройства (особенно на прошивках Xiaomi, Huawei, Samsung — там помогает отключение оптимизации батареи) и как это сказывается на расходе заряда.

Логи с устройства: `adb logcat -s ProxyService python.stdout python.stderr`.
